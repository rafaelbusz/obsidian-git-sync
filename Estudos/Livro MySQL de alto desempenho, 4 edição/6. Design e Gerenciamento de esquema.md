# Escolhendo tipos de dados
Escolher o tipo de dados correto é crucial para bom desempenho, as diretrizes a seguir podem ajudar você a fazer melhores escolhas:
## Menor geralmente é melhor
Tente usar o menor tipo de dado que pode armazenar e representar corretamente seus dados. Tipos de dados menores geralmente são mais rápidos porque usam menos espaço no disco, memória e no cache da CPU, também exigem menos ciclos de CPU para serem processados. Não subestimar o tamanho, porque porque aumentar o intervalo de tipos de dados em vários lugares pode ser uma operação dolorosa e demorada, escolha o menor que você acha que não excederá.
## Simples é bom
Inteiros são mais baratos de comparar do que caracteres. Exemplo armazenar data e horas nos tipos internos em vez de string, usar inteiros para endereços IP.
### Evite NULL se possível
Muitas tabelas incluem colunas anuláveis mesmo quando o aplicativo não precisa armazenar NULL( a ausência de valor), simplesmente porque é o padrão. É mais difícil para o banco de dados otimizar as consultas que se referem a colunas anuláveis porque elas se tornam índices, estatísticas de índice e comparações de valores mais complicados. Uma coluna anulável usa mais espaço de armazenamento e requer processamento especial dentro do banco. A melhoria de desempenho de alterar NULL para NOT NULL não é tão grande então não torne disso uma prioridade.

O primeiro passo para decidir qual tipo de dados usar para uma determinada coluna é determinar qual classe geral de tipos é apropriada: numérico, string, temporal e assim por diante. Isso geralmente é bem direto, mas mencionamos alguns casos especiais em que a escolha não é intuitiva.

O próximo passo é escolher o tipo específico. Muitos dos tipo de dados do mysql podem armazenar o mesmo tipo de dados, mas variam no intervalo de valores que podem armazenar, na precisão que permitem ou no espaço físico (em disco e na memória) que requerem. Alguns tipos de dados também têm comportamentos ou propriedades especiais.

Por exemplo, a DATETIME e a TIMESTAMP coluna podem armazenar o meso tipo de dados: data e hora, com precisão de um segundo. No entanto, TIMESTAMP usa apenas metade do espaço de armazenamento, reconhece fuso horário e tem recursos especiais de atualização automática. Por outro lado, tem um intervalo muito menor de valores permitidos e, às vezes, seus recursos especiais podem ser uma desvantagem.
## Números Inteiros
São dois tipos de números: números inteiros e números reais(números com uma parte fracionaria). Se estiver armazenando inteiros, use dos tipos inteiros: TINYINT, SMALLINT, MEDIUMINT, INT ou BIGINT. Eles exigem 8,16,24,32 e 64 bits de espaço de armazenamento, respectivamente. Eles podem armazenar valores de -2 ^(n-1)a 2 1, onde N é o número de bits de espaço de armazenamento que es usam.

Tipos inteiros podem ter o UNSIGNED atribuído,  que não permite valores negativos e aproximadamente dobra o limite superior de valores positivos que você pode armazenar. Tipos assinados e não assinados usam a mesma quantidade de espaço de armazenamentos e têm o mesmo desempenho, então use o que for melhor para se intervalo de dados.

O mysql permite que você especifique uma "largura" para tipos inteiros, como int(11). Isso não tem sentido para maioria dos aplicativos: ele não restringe o intervalo legal de valores, mas simplesmente especifica o número de caracteres que as ferramentas interativas do mysql reservarão para fins de exibição, não impacta em armazenamento, cálculos ou validação de dados.

## Número reais
Números reais são números que têm uma parte fracionária. No entanto, eles não são apenas para números fracionários; você também pode usar DECIMAL para armazenar inteiros que são tão grandes que não cabem em BIGINT. O mysql suporta tipos exatos e inexatos.
